0002 · Merge reports by demonstrated cause

owner Rafał Łuczun proposed reviewed 2026-10-28 · 0 days ago

Date: 28 October 2026 · Proposed by: Rafał Łuczun with Codex

Context

The review of #4471 shows that subjects and browser-derived intake tags do not reliably identify a defect. An incident can contain several causes. This proposal replaces 0001 when accepted by the desk. Record 0001 is preserved unchanged.

Decision

Read the body and consult tenant locale, booking form version and channel. Merge only when the cause is demonstrated to be the same. For this snapshot, causes.ts distinguishes the shared month-first parser from the booking-v3 month-first hint on a day-first form. Do not use browser locale, intake tags or subject equality as the deciding evidence.

Count each report ID once. Keep evidence that contradicts a classification visible and request a reproduction. Missing tenants or an unexplained symptom need investigation; leave them apart until a cause is established. Reconcile new arrivals while the desk works.

This original explorer demonstrates the exported tenant/form/channel classifier only. Its “same cause — merge” label is preliminary; it does not read the bodies or establish that merging is justified. Apply the evidence checks above before any merge.

This takes more reading than subject matching, but prevents a queued fix from hiding a different defect. It also merges different subjects that describe the same cause. Review the rule when new products, forms or symptoms appear; the current classifier covers only the date problems evidenced in this export.
